## U-03 · 💬 ตอบคำถาม "อะไรเป็นหลักเกณฑ์ mapping?"

ต้นถามว่าจะรู้ได้ยังไงว่าสินค้าไหนต้องถ่ายคู่กับอะไร — **หลักเกณฑ์มีอยู่ในระบบแล้ว**
ทุกสินค้ามีฟิลด์ `howto` (วิธีรับประทาน) ใน `lib/calc/vitamins.ts` ซึ่งบอกรูปแบบการใช้อยู่แล้ว เช่น
ชงน้ำ / กินกับอาหาร / หยดใต้ลิ้น / ใช้ภายนอก → **ภาพควรตรงกับ `howto` ของตัวเอง**

เกณฑ์ที่เสนอ (รอต้นเคาะ):
1. **ผงชง** → ถ่ายคู่แก้ว/ชงแล้ว (เช่น Ferty คู่แก้วเชค · Colla Telo คู่แก้วน้ำม่วง ตามที่ต้นยกตัวอย่าง)
2. **แคปซูล/เม็ด** → ถ่ายคู่แผงหรือเม็ดที่เทออกมา ให้เห็นว่าเป็นเม็ด
3. **น้ำ/ชอต** → ถ่ายขวดจริง ไม่ต้องมีภาชนะเสริม
4. **ใช้ภายนอก** → ถ่ายให้เห็นว่าไม่ใช่ของกิน

🔴 ข้อบังคับ: ภาพต้องไม่ขัดกับ `howto` ที่ระบบเขียนไว้ ถ้าจะเปลี่ยนวิธีใช้ ต้องแก้ทั้งภาพและข้อความพร้อมกัน
**ยังไม่ dev** — รอต้นยืนยันเกณฑ์ + รอไฟล์ภาพ

## U-04 · ✅ ช่วงตัวเลขที่ต่ำสุด = สูงสุด ขึ้นเลขเดียว

- เพิ่ม `fmtRange(min, max)` ใน `lib/calc/protein.ts` — เท่ากันเมื่อไหร่พิมพ์เลขเดียว
- ใช้ **ครบทั้ง 3 จุด** ที่แสดงเป้าโปรตีน:
  1. หน้าเครื่องมือโปรตีน (`app/tools/protein/page.tsx`) — ทั้งกรัมและ ก./กก.
  2. รายงานฉบับเต็ม (`components/report-view.tsx`)
  3. กล่อง "เป้าหมายของคุณต่อวัน" บนหน้าก่อนเข้า LINE (`planMetrics()` ใน `lib/report.ts`)
- **ไม่แตะสูตรและไม่แตะค่าอ้างอิงทางโภชนาการ** (ช่วงให้นมบุตร 1.3–1.3 ยังเป็นค่าเดิม) แก้เฉพาะการแสดงผล

> ⚠️ จุดที่ 3 หลุดไปตอนแรก เจอตอนทดสอบบนหน้าจริง — `planMetrics()` เป็นคนละฟังก์ชันกับอีก 2 จุด
> ตอนนี้มีเทสต์คุมทั้ง 3 จุดแล้ว

## U-05 · ✅ เติมด้วยโปรตีนเฟอร์ตี้ 1–2 ซอง/วัน (ค่าคงที่จากแบรนด์)

- เพิ่ม `FERTY_TOPUP = { min: 1, max: 2 }` + `fertyTopUpText()` เป็นแหล่งความจริงเดียว
- **เลิกคำนวณจำนวนซองจากน้ำหนักตัว** ในประโยคแนะนำ — คนหนัก 100 กก. เดิมถูกบอกให้กิน ~6 ซอง/วัน
- คงแถวเทียบเท่า "โปรตีนเฟอร์ตี้ ≈ N ซอง" ไว้เหมือนเดิม (คนละความหมาย: กินซองแทนโปรตีนทั้งวัน)
- ฝ่ายชายเปลี่ยนชื่อเป็น Ferta แต่จำนวนซองเท่ากัน

## U-06 · ✅ ผูก LINE แล้ว → ไม่ต้องโชว์รหัสซ้ำ

ทำตามที่ต้นเสนอ ซึ่งดีกว่าที่ผมเสนอไว้ (ผมเสนอ "ยุบเป็นลิงก์กดกาง")

- `app/r/[code]/page.tsx` เช็คฝั่ง server ว่า lead ของรหัสนี้มี `line_user_id` แล้วหรือยัง
- **ผูกแล้ว** → ซ่อนกล่องรหัส + ซ่อนบรรทัด "พิมพ์รหัสในแชท"
- **ยังไม่ผูก** (เปิดลิงก์เองหรือมีคนส่งต่อ) → ยังเห็นรหัส เพราะผูกบัญชีได้ด้วยการพิมพ์รหัสเท่านั้น
- ปุ่มเปลี่ยนเป็น **"กลับไปคุยกับแอดมิน"** ทุกกรณีตามที่ขอ
- เช็คพลาด/ไม่พบ = ถือว่ายังไม่ผูกเสมอ (fail-safe ไม่ตัดทางผูกบัญชี)

⚠️ ยังเป็นการ "เปิดแอป LINE ไปที่ OA" ไม่ใช่เด้งกลับหน้าแชทอัตโนมัติ — อันนั้นต้องใช้ LIFF ซึ่งรอ LINE Login channel

  ซึ่ง **เดิมถูกดันตกจอทั้งหมด ไม่มีลูกค้าคนไหนได้เห็นเลย**

## U-08 · 📝 บันทึกรอแบรนด์ ยังไม่ dev

ต้นสั่ง "ทำ Note ไว้รอ confirm" — คำถามที่ต้องได้คำตอบก่อนเติมตาราง:

1. **อะโวคาโด** มีโปรตีนต่ำมาก (~2 ก./100 ก.) การใส่ในตาราง "แหล่งโปรตีน" เสี่ยงให้เข้าใจผิดว่ากินแล้วได้โปรตีนพอ
   → ใส่จริงไหม หรือย้ายไปหัวข้อ "ไขมันดี" ซึ่งเป็นจุดแข็งจริงของอะโวคาโด
2. **นม / ถั่ว** ต้องระบุชนิด — นมวัว/นมแพะ · ถั่วอัลมอนด์/วอลนัต — เพราะค่าโปรตีนต่างกันหลายเท่า
3. ขอค่าโปรตีนต่อหน่วยของ **เนื้อวัว · หมู · นม · ถั่ว · อะโวคาโด · กุ้ง** จากทีมครูก้อย

🔒 `lib/calc/food-reference.ts` ล็อกกฎไว้ว่าทุกตัวเลขต้องมาจากเอกสารโปรเจกต์ **ห้ามเติมจากความจำ**
ต้องเติมลง `docs/nutrition-protocol.md` ก่อน แล้วค่อยแก้โค้ด

## U-09 · ✅ ลำดับชั้นตัวอักษรหน้าก่อนเข้า LINE

- **ตัวเลขเป้าหมายเด่นที่สุด** (`text-base font-semibold`) · หัวข้อ `text-lg` · ป้ายกำกับกับเหตุผล `text-xs` สีจาง
- ชื่อสินค้าแยกบรรทัดใหญ่/หนา · เหตุผลอยู่ใต้ตัวเล็กและจาง (เดิมอยู่บรรทัดเดียวกันคั่นด้วยขีด)
- เพิ่มเส้นคั่นจาง ๆ ระหว่างรายการ + `leading-relaxed` (ภาษาไทยมีสระบน-ล่าง ต้องการระยะบรรทัดมากกว่าอังกฤษ)
