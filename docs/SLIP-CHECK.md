# ตรวจสลิปโอนเงินเอง (Thunder Solution API)

> โค้ด: [`lib/slip.ts`](../lib/slip.ts) · [`app/api/line/slip-image/route.ts`](../app/api/line/slip-image/route.ts) · เทสต์: [`lib/slip.test.ts`](../lib/slip.test.ts)
> เอกสาร Thunder: https://document.thunder.in.th/th/v2/ · base URL `https://api.thunder.in.th/v2`

แทนที่จะ**ส่งต่อ** event ให้บอทของ Thunder (ดู [LINE-WEBHOOK-RELAY.md](LINE-WEBHOOK-RELAY.md))
webhook ของเรารับภาพสลิปแล้ว**เรียก API ตรวจเอง** แล้วตอบผลกลับในแชท

```
ผู้ใช้ส่งภาพสลิปใน LINE
      ↓  webhook (message.type = "image")
ออกลิงก์ชั่วคราวเซ็น HMAC อายุ 2 นาที → /api/line/slip-image?t=…
      ↓  POST /verify/bank {url, checkDuplicate:true}
Thunder มาดึงภาพจากลิงก์นั้น → ตรวจ → คืนข้อมูลสลิป
      ↓
ตอบในแชท: ยอดเงิน · ผู้โอน · ผู้รับ · เวลา · เลขอ้างอิง
```

---

## ⚠️ เอกสารกับ API จริงไม่ตรงกัน (ทดสอบเอง 20 ส.ค. 2569)

เอกสารบอกว่าส่งภาพได้ 3 ทาง แต่ยิงจริงแล้วใช้ได้ทางเดียว:

| วิธีตามเอกสาร | ผลจริง |
|---|---|
| base64 ในฟิลด์ `image` | ❌ `400` — *"image: Invalid input: expected file, received string"* |
| multipart file (`file`/`image`/`slip`/`photo`) | ❌ `400` — *"Please provide either a payload string, a image file…"* เหมือนไม่ถูก parse เลย (ลองทั้ง curl และ `FormData` ของ Node) |
| **ฟิลด์ `url`** | ✅ **ใช้ได้** — Thunder ไปดึงภาพเองจริง |
| ฟิลด์ `payload` (สตริง QR) | ✅ ใช้ได้ แต่เราต้องถอด QR เองก่อน |

จึงเลือกโหมด `url` · แต่ภาพใน LINE ต้องมี access token ถึงจะโหลดได้ Thunder ดึงตรงไม่ได้
เลยต้องมี `/api/line/slip-image` เป็นทางผ่านชั่วคราว

> 💡 ถ้าวันหนึ่ง Thunder ยืนยันชื่อฟิลด์อัปโหลดที่ถูกต้อง เปลี่ยนมาส่งไฟล์ตรงจะง่ายและปลอดภัยกว่านี้
> — **แนะนำให้ถามซัพพอร์ต Thunder** เพราะเอกสารที่เผยแพร่อยู่ไม่ตรงกับ API จริง

**ข้อดีที่เจอ:** error แบบ `VALIDATION_ERROR` **ไม่กินโควตา** (ทดสอบซ้ำหลายรอบแล้วโควตายัง 100/100)

## 🔴 กฎที่ห้ามผิด

### 1. ห้ามเปิดพร้อมกับ relay — ระบบปิดให้เองถ้าเผลอ
`replyToken` ของ LINE ใช้ได้ครั้งเดียว ถ้าเปิดทั้ง `SLIP_CHECK_ENABLED` และ `LINE_RELAY_WEBHOOK_URL`
บอทของ Thunder จะตอบภาพเดียวกันด้วย แล้วฝ่ายใดฝ่ายหนึ่งจะพัง

**ระบบจะปิดการตรวจสลิปของเราอัตโนมัติเมื่อ relay ยังเปิดอยู่** แล้วถอยไปสถานะเดิมที่ปลอดภัย
(ปล่อยให้บอทของ Thunder ตรวจเหมือนเดิม) — เพิ่มหลังเกิดขึ้นจริงบน production 20 ส.ค. 69
ซึ่งแก้ env ไม่ติดอยู่พักใหญ่ การพึ่งแค่ "คำเตือนให้คนไปแก้เอง" ไม่พอสำหรับเรื่องเงิน

diagnostic ที่ `GET /api/line/webhook` แยก 2 ฟิลด์:
- `slip` = ตั้งค่าไว้ให้เปิดไหม
- `slipActive` = **ทำงานจริงไหม** ← ดูตัวนี้
ถ้า `slip:"on"` แต่ `slipActive:false` แปลว่าโดนปิดอัตโนมัติเพราะ relay ยังเปิด

### 2. ไม่แน่ใจ = ต้องไม่ผ่าน
ผลตรวจสลิปคือเรื่องเงิน ถ้าตรวจพลาดลูกค้าอาจส่งของโดยไม่ได้รับเงินจริง
ทุกกรณีที่ระบบไม่มั่นใจ (เน็ตล่ม · โควตาหมด · key เสีย · อ่านสลิปไม่ออก) จะตอบว่า
"แอดมินจะตรวจให้เอง" **ไม่มีทางตอบว่าผ่านโดยไม่ได้ตรวจ**

### 3. เลขบัญชีผู้รับ — กันโกงที่สำคัญที่สุด
ถ้าไม่ตั้ง `THUNDER_RECEIVER_ACCOUNT` ลูกค้าส่งสลิปจริงที่โอนเข้าบัญชี**ใครก็ได้** แล้วระบบจะอ่านให้เฉย ๆ

Thunder ปิดเลขบัญชีเหลือ 3 หลัก (`xxx-x-xx789-x`) ความแม่นยำจึงเป็นแบบนี้:
- **เลขไม่ตรง → สรุปได้แน่นอนว่าคนละบัญชี** ปฏิเสธได้เต็มปาก
- **เลขตรง → แค่ "ไม่ขัดกัน"** (3 หลักซ้ำกันได้ราว 1 ใน 1,000) **ไม่ใช่การยืนยัน**
  ข้อความตอบผู้ใช้จึงเขียนว่า "แอดมินจะยืนยันยอดอีกครั้ง" เสมอ ห้ามเคลมว่ายืนยันแล้ว

### 4. API key ห้ามอยู่ในโค้ด
อ่านจาก env `THUNDER_API_KEY` เท่านั้น · ห้าม log · ห้ามส่งกลับไปในคำตอบ LINE
(มีเทสต์คุมว่าไม่มีข้อความไหนถึงผู้ใช้มี key หรือชื่อ error code หลุดออกไป)

## ตั้งค่า

| ตัวแปร | ค่า | จำเป็น |
|---|---|---|
| `SLIP_CHECK_ENABLED` | `1` | ✅ ไม่ตั้ง = ปิด |
| `THUNDER_API_KEY` | key จาก Thunder | ✅ |
| `THUNDER_RECEIVER_ACCOUNT` | เลขบัญชีร้าน คั่นด้วยจุลภาคได้ | 🔴 ควรตั้งอย่างยิ่ง |
| `SLIP_IMAGE_SECRET` | `openssl rand -base64 32` | ไม่ตั้ง = ใช้ `LINE_CHANNEL_SECRET` แทน |
| `NEXT_PUBLIC_APP_URL` | โดเมนจริงของ deployment | ✅ Thunder ใช้ดึงภาพ |
| `LINE_RELAY_WEBHOOK_URL` | **ต้องล้างให้ว่าง** | 🔴 |

ตรวจสถานะ: `curl -s <url>/api/line/webhook` → ต้องเห็น **`"slipActive":true`** และ **ไม่มี** ฟิลด์ `warning`

## 🔒 ความเป็นส่วนตัวของลิงก์ภาพชั่วคราว

ภาพสลิปมีชื่อผู้โอน/ผู้รับและเลขบัญชีบางส่วน = ข้อมูลส่วนบุคคล `/api/line/slip-image` จึง:
- เดา URL ไม่ได้ (โทเคนเซ็น HMAC) · อายุ **2 นาที** · โทเคนผิด/หมดอายุ = 404 เปล่า ๆ
- **ไม่เก็บไฟล์ไว้ที่ไหนเลย** — อ่านจาก LINE แล้วส่งต่อทันที ไม่เขียนลงดิสก์/ฐานข้อมูล
- `Cache-Control: no-store` + `X-Robots-Tag: noindex`

## วิธีทดสอบ

1. ตั้ง env ครบ + ล้าง `LINE_RELAY_WEBHOOK_URL` → Redeploy
2. `curl -s <url>/api/line/webhook` → `"slip":"on"` ไม่มี `warning`
3. ส่ง**ภาพสลิปจริง** เข้า LINE OA → ต้องได้ยอดเงิน/ผู้โอน/เวลา/เลขอ้างอิงกลับมา
4. ส่ง**ภาพเดิมซ้ำ** → ต้องได้ "สลิปนี้เคยถูกใช้ยืนยันไปแล้ว" (`checkDuplicate`)
5. ส่ง**ภาพที่ไม่ใช่สลิป** → ต้องได้ "อ่านสลิปจากภาพนี้ไม่ได้"
6. ถ้าตั้ง `THUNDER_RECEIVER_ACCOUNT` แล้ว ลองสลิปที่โอนเข้าบัญชีอื่น → ต้องได้ "โอนเข้าบัญชีอื่น"

> ⚠️ ทุกครั้งที่ตรวจ**สลิปจริงสำเร็จ** จะกินโควตา 1 ครั้ง (จาก 100)
