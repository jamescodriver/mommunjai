## Problem Statement

หลังใช้งานจริง ทีมครูก้อยพบว่าคำแนะนำสินค้าที่แอปให้ **ไม่ตรงกับวิธีที่ทีมแนะนำลูกค้าจริง** — แอปแนะนำชุด "core" ชุดเดียวกันให้ทุกคนโดยไม่แยกตามปัญหา ขณะที่ทีมมีตาราง mapping สินค้าต่อปัญหาที่ใช้อยู่จริงในการปรึกษาลูกค้า และแบบสอบถามยังเก็บข้อมูลไม่พอจะให้คำแนะนำเฉพาะบุคคล (ไม่มีน้ำหนัก/ส่วนสูง/การนอน/การออกกำลังกาย) ทำให้รายงาน 90 วันที่ส่งให้ลูกค้า **ทั่วไปเกินกว่าจะรู้สึกว่า "ทำมาเพื่อฉัน"** ซึ่งเป็นจุดขายหลักที่ใช้ดึงลูกค้าเข้า LINE OA

ผลกระทบถ้าไม่แก้: ลูกค้าที่กรอกแบบสอบถามได้คำแนะนำที่แอดมินต้องแก้ใหม่ทั้งหมดตอนคุยใน LINE — เสียทั้งความน่าเชื่อถือของแอปและเวลาแอดมิน

---

## Goals

1. **คำแนะนำสินค้าตรงกับตาราง mapping ที่ทีมใช้จริง** — ติ๊กปัญหาไหน ได้สินค้าชุดนั้นเป๊ะ ไม่ใช่ชุดเดียวกันทุกคน (TS-12)
2. **เก็บข้อมูลพอจะคำนวณคำแนะนำเฉพาะบุคคลได้** — น้ำหนัก/ส่วนสูง/การนอน/การออกกำลังกาย ในทุก stage (TS-04, TS-06)
3. **รายงานฉบับเต็มอ่านแล้วรู้ว่า "นี่ของฉัน"** — เห็นตัวเลขของตัวเอง (BMI/น้ำ/นอน/โปรตีน/ไขมันดี) แทนกรอบทั่วไป 1-2-3-4 (TS-15)
4. **แต่ละ stage ถามเฉพาะสิ่งที่เกี่ยวกับตัวเอง** — เตรียมตั้งครรภ์/ให้นมบุตร ไม่ต้องเจอคำถามกระบวนการทางการแพทย์ (TS-05, TS-11)
5. **ฝ่ายชายไม่ใช่พลเมืองชั้นสอง** — ได้แบบสอบถามสุขภาพชุดเดียวกับหญิง + คำถามพฤติกรรมเฉพาะ และถูกดึงเข้ามาเมื่อผู้หญิงติ๊ก "ปัญหาจากฝ่ายชาย" (TS-06, TS-07)

---

## Non-Goals

1. **ไม่ทำ e-commerce/ตะกร้าสินค้า** — ยังจบที่ส่ง ticket ไปคุยแอดมินใน LINE OA เหมือนเดิม
2. **ไม่เชื่อม GFC lab-booking / โค้ดส่วนลด** — ยัง block รอ partnership (PDF-18 ส่วนที่เหลือ) รอบนี้ทำเฉพาะส่วนความรู้เหมือน R10
3. **ไม่ทำ LIFF เต็มรูป** — ยังใช้ resume-token ผ่านปุ่มข้อความ Rich Menu เหมือนเดิม
4. **ไม่แตะระบบ identity/consent/PDPA ที่ทำเสร็จแล้ว** — R7/PDF-05/06 ยังใช้ของเดิมทั้งหมด
5. **ไม่ทำ AI แปลผลรูปอาหาร** — ยัง Phase 2 (PDF-11)
6. **ไม่เก็บผลตรวจ lab จริงของผู้ใช้** — `/tools/labs` ยังเป็นความรู้อย่างเดียว ไม่รับ input ค่าผลตรวจ (ลดภาระ PDPA)

## User Stories

**ผู้หญิงมีบุตรยาก (persona หลัก)**
- ในฐานะคนที่ติ๊กว่ามี PCOS ฉันอยากได้ PCO-VIT ในรายการแนะนำ เพราะนั่นคือตัวที่ตรงกับปัญหาฉันจริง ๆ ไม่ใช่ชุดทั่วไปที่ใครก็ได้
- ในฐานะคนที่ติ๊ก "น้ำหนักเกิน" ฉันอยากเห็นตัวเลข BMI ของตัวเองพร้อมรู้ว่าอยู่ระดับไหน เพื่อรู้ว่าต้องขยับเท่าไหร่ ไม่ใช่แค่ได้ยินว่า "เกินนิดหน่อย"
- ในฐานะคนที่ติ๊ก "ปัญหาจากฝ่ายชาย" ฉันอยากกรอกข้อมูลของสามีด้วย เพราะปัญหาอยู่ที่เขา คำแนะนำที่ไม่ถามถึงเขาเลยย่อมไม่ตรง

**ผู้หญิงเตรียมตั้งครรภ์**
- ในฐานะคนที่ยังไม่ได้เข้ากระบวนการทางการแพทย์ ฉันไม่อยากเจอคำถาม IUI/IVF ที่ไม่เกี่ยวกับฉัน เพราะทำให้รู้สึกว่ามาผิดที่
- ในฐานะคนอายุ 38 ฉันอยากได้คำแนะนำที่ต่างจากคนอายุ 28 เพราะเวลาของฉันเหลือน้อยกว่า

**ฝ่ายชาย**
- ในฐานะฝ่ายชาย ฉันอยากถูกถามเรื่องสูบบุหรี่/ดื่ม/ความเครียด เพราะนั่นคือสิ่งที่กระทบคุณภาพอสุจิจริง ๆ ไม่ใช่ถามแค่ว่าอายุเท่าไหร่

**แม่ตั้งครรภ์ / ให้นมบุตร**
- ในฐานะแม่ตั้งครรภ์ 20 สัปดาห์ ฉันอยากรู้ว่าตอนนี้ลูกกำลังพัฒนาอะไร ต้องกินอะไร และสัญญาณอันตรายคืออะไร เพราะเป็นเรื่องที่ค้นเองแล้วเจอข้อมูลขัดกันเต็มไปหมด
- ในฐานะแม่ให้นม ฉันอยากรู้ตารางปั๊มนมและลูกวัยนี้ควรกินกี่ออนซ์ เพราะเป็นคำถามที่ถามทุกวัน

**ทุก persona — หลังกรอกเสร็จ**
- ในฐานะคนที่เพิ่งกรอกแบบสอบถามจบ ฉันอยากเห็นตัวเลขของฉันเอง (น้ำ/นอน/โปรตีน/ไขมันดี) เพื่อรู้สึกว่าคุ้มที่กรอก และอยากเอา ticket ไปคุยต่อ

## Requirements

### P0 — Must Have

---

#### R1. หน้าแรก: ปุ่มการ์ด "เตรียมตั้งครรภ์" → "ฝ่ายหญิง" `[TS-01]`

เปลี่ยนข้อความปุ่มหลักของการ์ด "เตรียมตั้งครรภ์" จาก "เริ่มเลย →" เป็น **"ฝ่ายหญิง →"** ให้เป็นคู่กับปุ่มรอง "ฝ่ายชาย →" ที่มีอยู่แล้ว

**Acceptance criteria**
- [ ] `TC-01-01` ปุ่มหลักการ์ดเตรียมตั้งครรภ์ = "ฝ่ายหญิง →" และยังลิงก์ไป `/plan?stage=prep`
- [ ] `TC-01-02` การ์ดอีก 3 ใบ (มีบุตรยาก/ตั้งครรภ์แล้ว/ให้นมบุตร) **ยังเป็น "เริ่มเลย →" เหมือนเดิม** ไม่เปลี่ยนตาม

---

#### R2. อายุ 35-39 / 40+ → เพิ่ม A.O.S `[TS-02]`

เพิ่มกฎใหม่: ช่วงอายุ `35–39` หรือ `40+` → A.O.S เข้าไปในรายการแนะนำ (เดิมผูกกับ artPlan/stage เท่านั้น)

**Acceptance criteria**
- [ ] `TC-02-01` อายุ 35–39 → มี A.O.S
- [ ] `TC-02-02` อายุ 40+ → มี A.O.S
- [ ] `TC-02-03` อายุต่ำกว่า 35 และไม่มีปัจจัยอื่น → **ไม่มี** A.O.S
- [ ] `TC-02-04` เข้าเงื่อนไขจากทั้งอายุและ artPlan พร้อมกัน → A.O.S ปรากฏ **ครั้งเดียว** (dedupe)
- [ ] 🔒 **ข้อบังคับความปลอดภัย:** กฎอายุนี้ต้องผ่าน `allowedIn()` (Safety Matrix) เหมือนสินค้าอื่น — A.O.S มี `stop.pregnant = true` ดังนั้น **แม่ตั้งครรภ์อายุ 40+ ต้องไม่ได้ A.O.S** ห้าม bypass filter เพื่อให้กฎอายุทำงาน

---

#### R3. "เตรียมผนังมดลูก" → ชุดสินค้าเฉพาะ `[TS-03]`

เมื่อ `artPlan === "เตรียมผนังมดลูก"` → แนะนำ **Colla Telo + ดอกคำฝอย + น้ำมันละหุ่ง + Ferty Probiotics**

**Acceptance criteria**
- [ ] `TC-03-01` เลือก "เตรียมผนังมดลูก" → เห็นครบทั้ง 4 รายการ
- [ ] `TC-03-02` 🔒 **คำเตือน stop-rule ของดอกคำฝอย/น้ำมันละหุ่งต้องยังแสดงครบ** (หยุดช่วงตกไข่ · หลังใส่ตัวอ่อน · ตั้งครรภ์) ห้ามหายไปเพราะกฎใหม่นี้ — ทั้งคู่เป็นสินค้ากระตุ้นมดลูก การแนะนำตอน "เตรียมผนัง" ซึ่งมักใกล้ช่วงใส่ตัวอ่อนมาก จำเป็นต้องมีคำเตือนกำกับเสมอ
- [ ] ผูกกฎกับ **ค่า `artPlan`** ไม่ใช่ `stage === "prep"` (เพราะ R5 ตัดคำถาม ART ออกจาก prep แล้ว — ดู §Reversals)

---

#### R4. ขั้น "เล่าเรื่องสุขภาพ" — เพิ่ม 4 ฟิลด์ + แยกช่อง PCOS `[TS-04]`

เพิ่มในขั้น health ของ **ทุก stage**:
1. **น้ำหนัก (กก.) + ส่วนสูง (ซม.)** — เดิมถามส่วนสูงเฉพาะตอนติ๊ก "น้ำหนักเกิน" เท่านั้น ตอนนี้ถามทุกคน (จำเป็นสำหรับ BMI ใน R13/R15)
2. **เวลานอน** — เลือกเวลาเข้านอน + เวลาตื่น (time picker 2 ช่อง)
3. **ความถี่ออกกำลังกาย** — dropdown: `0 ครั้ง/สัปดาห์` · `1–2 ครั้ง` · `3–4 ครั้ง` · `ทุกวัน`
4. **PCOS แยก 2 ช่อง** — จากเดิมช่องเดียว "มีภาวะ PCOS / ไม่แน่ใจ" → แยกเป็น **"มีภาวะ PCOS"** กับ **"ไม่แน่ใจ"**

**กติกา PCOS 3 สถานะ** (จากคอมเมนต์ TS-04: *"ถ้ามี ก็แนะนำ PCO VIT"*):
| สถานะ | ผลต่อสินค้า | ผลต่อข้อความ |
|---|---|---|
| **มี** (`yes`) | ✅ แนะนำ PCO-VIT | ข้อความ PCOS-aware เดิมทั้งหมด |
| **ไม่แน่ใจ** (`unsure`) | ❌ **ไม่แนะนำ PCO-VIT** | เพิ่มข้อความชวนไปตรวจยืนยันกับแพทย์ (ไม่ใช่บอกว่า "คุณเป็น") |
| **ไม่ติ๊กเลย** (`no`) | ไม่มีผล | ไม่มีข้อความ PCOS |

**Acceptance criteria**
- [ ] `TC-04-01` มีช่องน้ำหนัก + ส่วนสูง
- [ ] `TC-04-02` มี time picker เข้านอน/ตื่นนอน
- [ ] `TC-04-03` dropdown ออกกำลังกาย 4 ตัวเลือกตามที่ระบุ
- [ ] `TC-04-04` PCOS เป็น 2 ช่องแยกกัน ไม่ใช่ช่องรวม
- [ ] `TC-04-05` ติ๊ก "ไม่แน่ใจ" → **ไม่มี PCO-VIT** ในรายการ แต่มีข้อความแนะนำให้ตรวจยืนยัน
- [ ] ติ๊ก "มี" กับ "ไม่แน่ใจ" พร้อมกันไม่ได้ (exclusive — ติ๊กอันหนึ่งอีกอันหลุด)
- [ ] ข้อมูลใหม่ทั้งหมดถูกบันทึกลง DB และ prefill กลับได้เมื่อกลับมาทำใหม่ผ่าน resume-link

---

#### R5. เตรียมตั้งครรภ์ — ตัดขั้น ART ออก `[TS-05]`

`stage === "prep"` ไม่ต้องเจอคำถาม "เข้าสู่กระบวนการทางการแพทย์ไหมคะ?"

**Acceptance criteria**
- [ ] `TC-05-01` prep เดินจนจบไม่เจอคำถามนี้
- [ ] `TC-05-02` `infertility` / `pregnant` / `male` **ยังเจอเหมือนเดิม**
- [ ] `TC-05-03` prep ที่ไม่ถูกถาม → บันทึก `art_plan = "ยัง"` (default) ไม่ใช่ null — กัน logic อื่นที่พึ่ง artPlan พัง

---

#### R6. ฝ่ายชาย — ฟิลด์สุขภาพ + พฤติกรรม + กฎสินค้า `[TS-06]`

`stage === "male"` ได้ฟิลด์ชุดเดียวกับ R4 (น้ำหนัก/ส่วนสูง/เวลานอน/ความถี่ออกกำลังกาย) **บวก** checkbox พฤติกรรม 3 ข้อ: **สูบบุหรี่ · ดื่มแอลกอฮอล์ · เครียด** (เลือกได้หลายข้อ)

**กฎสินค้า** (คอมเมนต์ TC-06-07 ระบุ **`>= 2`**):
```
จำนวนข้อที่ติ๊ก >= 2        → A.O.S + Motila1
มิฉะนั้น ติ๊ก "เครียด"       → A.O.S
มิฉะนั้น ติ๊ก บุหรี่ หรือ ดื่ม → Motila1
ไม่ติ๊กเลย                  → ไม่เพิ่มทั้งคู่จากกฎนี้
```

**Acceptance criteria**
- [ ] `TC-06-01` male มีฟิลด์สุขภาพครบเหมือนหญิง
- [ ] `TC-06-02` มี checkbox 3 ข้อ เลือกได้หลายข้อ
- [ ] `TC-06-03` ติ๊ก "เครียด" อย่างเดียว → มี A.O.S
- [ ] `TC-06-04` ติ๊ก "ดื่ม" อย่างเดียว → มี Motila1
- [ ] `TC-06-05` ติ๊ก "บุหรี่" อย่างเดียว → มี Motila1

> #### (ก) หัวข้อ "อาหารเพิ่มน้ำนม" ชนกับผลวิจัยของสินค้าที่แบรนด์ขายเอง
>
> | สินค้า | หลักฐานที่ดีที่สุดที่มี | คำตัดสิน |
> |---|---|---|
> | **น้ำหัวปลี** (฿1,850) | **RCT ไทย จุฬาฯ ปิดตาสองทาง มีกลุ่มยาหลอก n=70** — วันที่ 7: **333 vs 350 มล. (p=0.73)** สรุปว่า *"did not increase the BMV"* | ⛔ **มีหลักฐานเชิงลบโดยตรง** — แย่กว่า "ไม่มีข้อมูล" · **ห้ามเคลมเรื่องเพิ่มน้ำนมเด็ดขาด** |
> | **ขิงทอง** (฿650) | RCT ไทย มศว n=63 — วันที่ 3 บวกจริง (p<0.01) แต่ **วันที่ 7 หายไป (p=0.24)** ผู้เขียนใช้คำว่า "promising" ไม่ใช่ "effective" | ⚠️ เคลมได้แค่ *"งานวิจัยไทยพบว่าอาจช่วยใน 3 วันแรก แต่ผลไม่คงอยู่ถึงวันที่ 7"* |
> | **ซุปไก่ดำ** (฿1,800) | **ไม่พบงานวิจัยเรื่องน้ำนมเลย** | ⛔ ขายเป็น "อาหารบำรุงกำลัง/โปรตีน" ได้ · **ห้ามเคลมน้ำนม** |
>
> องค์กรวิชาชีพ **ABM Protocol #9** ระบุ verbatim ว่า *"ABM cannot recommend any specific galactogogue at this time"* และ Cochrane 2020 (41 RCT) ให้ certainty **low to very low** (I²=99% = งานวิจัยขัดกันเองแทบสมบูรณ์) · แม้แต่ **"ดื่มน้ำเยอะ ๆ"** Cochrane ก็พบว่า *ไม่มี RCT รองรับ* และการศึกษาเดียวที่มีพบว่า **ไม่ช่วย**
>
> **✅ เคาะแล้ว (ต้น 31/7): *"เปลี่ยนกรอบเลย"*** → เปลี่ยนหัวข้อจาก **"อาหารเพิ่มน้ำนม"** เป็น **"อาหารบำรุงแม่หลังคลอด"**
> เพราะ **แม่ให้นมต้องการพลังงานเพิ่ม 450–500 แคลอรี่/วัน (ACOG)** — เป็นความจริง 100% ที่พิสูจน์ได้ และสินค้าโปรตีน/ซุป/เครื่องดื่มบำรุงตอบโจทย์นี้ได้ตรง ๆ โดยไม่ต้องเคลมเรื่องน้ำนมเลย · ส่วนหัวปลี/ขิง นำเสนอเป็น **"ภูมิปัญญาไทย"** พร้อมหมายเหตุหลักฐานอย่างโปร่งใส
> และให้ **"สิ่งที่เพิ่มน้ำนมได้จริง" เป็นพระเอกของหน้า** — ABM ยืนยันว่ากลไกจริงคือ **การระบายน้ำนมออกบ่อยและเกลี้ยง** (autocrine control) ไม่ใช่สมุนไพร
>
> #### (ข) 🔴 พ.ร.บ.นมผง — ความเสี่ยงทางกฎหมายที่ผูกกับตัวแอปเอง
> - **คำตัดสิน: นมแพะ "สำหรับแม่" อยู่นอกขอบเขต พ.ร.บ.** — ขอบเขตกำหนดโดย **ฉลากและการตลาด** ไม่ใช่โดยว่าใครดื่ม (ยืนยันจากประกาศ 2567 + คำชี้แจงกรมอนามัย)
> - **แต่จะผิดกฎหมายทันทีเมื่อ** creative ใส่: ภาพทารก · ไอคอนขวดนม/จุกนม · ตัวเลขช่วงอายุ (1+/2+) · หรือข้อความทำนอง *"แม่กินแล้วน้ำนมดีต่อลูก"*
> - ⚠️ **§14 ผูกกับ "ผู้ใด" = ตัวแอปเองก็เป็นผู้กระทำได้ โทษจำคุกสูงสุด 1 ปี** ไม่ใช่แค่แบรนด์

#### R15. รายงานฉบับเต็ม — โครงใหม่ Part 1 / Part 2 `[TS-15]`

คอมเมนต์ TC-15-01: *"ปรับแทนที่เลย"* → **แทนที่โครงเดิม** (pillars 5 ด้าน + แผน 3 เฟส 90 วัน) ทั้งหมด

**โครงใหม่:**

**Part 1 — ข้อมูลของคุณ**
- BMI + แถบสี + ระดับ (R13 · TC-15-03 ยืนยันให้แสดง)
- เป้าน้ำดื่มต่อวัน (จาก `lib/calc/water.ts`)
- ชั่วโมงนอนที่แนะนำ + เทียบกับเวลานอนจริงที่กรอก (R4)
- รูปแบบออกกำลังกายที่เหมาะ (จาก `lib/calc/exercise.ts` + ความถี่ที่กรอกใน R4)

**Part 2 — โภชนาการของคุณ**
- โปรตีน = ... กรัม/วัน (จาก `lib/calc/protein.ts`)
- น้ำ = ... มล./วัน
- **ไขมันดี** — ✅ ค้นข้อมูลเสร็จแล้ว → `docs/GOOD-FAT-PREGNANCY-RESEARCH-BRIEF.md` + `docs/GOOD-FAT-BY-CATEGORY-RESEARCH-BRIEF.md` (คอมเมนต์ TC-15-05)
- ตารางอ้างอิงโปรตีนต่ออาหาร 100 กรัม + ผักแนะนำ + ผลไม้แนะนำ

> #### ⚠️ ผลวิจัยไขมันดี — สิ่งที่ทำได้จริง vs สิ่งที่ทำไม่ได้
>
> คำขอเดิมคือ "แนะนำไขมันดีตาม cat เรา" (5 หมวด) — แต่งานวิจัยที่อ่านต้นฉบับ guideline จริง 4 ฉบับ (FAO/WHO, ASRM 2022, ESHRE 2023, AUA/ASRM 2024) พบว่า **มีตัวเลขที่มีแหล่งอ้างอิงจริงอยู่แค่ 2 ค่าเท่านั้น**:
>
> | หมวด | เป้า EPA+DHA | ที่มา |
> |---|---|---|
> | `prep` · `infertility` · `male` | **250 มก./วัน** | FAO/WHO ค่าผู้ใหญ่ทั่วไป |
> | `pregnant` · `lactating` | **300 มก./วัน** (โดย DHA ≥200 มก.) | FAO/WHO Table 7.2 (ครอบคลุมทั้งตั้งครรภ์และให้นม) |
>
> **การสร้างเป้าตัวเลขแยก 5 หมวด = การแต่งตัวเลขขึ้นเอง** ห้ามทำ (ผิดกฎ "ห้ามเดา" ของโปรเจกต์)
>
> **สิ่งที่ต่างกันจริงตามหมวด** คือ *เหตุผล* และ *ไขมันที่ต้องเลี่ยง* ไม่ใช่ตัวเลข:
> - `infertility` — ASRM 2022 ระบุตรงว่า *"ไม่มีหลักฐานเพียงพอว่าอาหารหรือสารอาหารชนิดใดเพิ่มการเจริญพันธุ์ตามธรรมชาติได้"* และ ESHRE 2023 ไม่พูดถึง omega-3 เลย → **ต้องไม่เคลมว่าไขมันดีช่วยให้ท้องง่ายขึ้น** ใช้ได้แค่ในฐานะโภชนาการพื้นฐานที่ดี
> - `prep` — งานวิจัย Chavarro 2007 (ไขมันทรานส์ ↔ ภาวะไข่ไม่ตก) เป็น observational RR 1.73 ช่วงความเชื่อมั่นกว้าง → ใช้เป็นเหตุผล **"เลี่ยงไขมันทรานส์"** ได้ แต่ห้ามยกเป็นการรับประกันผล
> - `male` — AUA/ASRM 2024 ระบุว่าอาหารเสริมสำหรับภาวะมีบุตรยากชาย *"มีประโยชน์ทางคลินิกที่น่าสงสัย"* (Grade B) และ**ไม่มีข้อมูลอัตราการตั้งครรภ์/คลอดมีชีพเลย** → หลักฐานฝั่ง "เลี่ยงไขมันทรานส์/อิ่มตัวเกิน" แข็งแรงกว่าฝั่ง "กิน omega-3 เพิ่ม" ต้องเขียนให้ตรงตามนั้น
> - `pregnant` · `lactating` — ไขมันทรานส์ต้อง **"ต่ำที่สุดเท่าที่ทำได้"** เข้มกว่าคนทั่วไป (FAO/WHO Chapter 7)
>
> **ข้อความบังคับในแอป:** ต้องแยกให้ชัดว่า "ไขมันดีทั่วไป" (น้ำมันมะกอก/อะโวคาโด/ถั่ว) **ไม่ใช่แหล่ง DHA** — DHA ต้องมาจากปลาทะเล/สาหร่ายเท่านั้น ถ้าเขียนรวมกันผู้ใช้จะเข้าใจผิดว่ากินน้ำมันมะกอกเยอะแล้วได้ DHA พอ

**ตารางแนะนำวิตามิน** — 3 คอลัมน์ (ผลิตภัณฑ์ / วิธีรับประทาน / ประโยชน์) + **รูปสินค้า**
- คอมเมนต์ TC-15-07: *"ถ้ามีก็แสดง ไม่มีก็ไม่ต้องแสดง"* → มีรูปแล้ว 19 รายการที่ `assets/products/` (ตัดจาก leaflet) — สินค้าที่ไม่มีรูป (PCO-VIT, Ferta, MZ-All, Motila1, นมแพะ, ซุปไก่ดำ, น้ำหัวปลี) ให้แสดงแถวโดยไม่มีรูป ไม่ใช่ซ่อนสินค้า

**ปิดท้าย:** ปุ่มแนะนำเมนู (ภาพจานอาหารตัวอย่าง) + ปุ่มทักแอดมิน (`AdminHandoffCta` ที่มีอยู่แล้ว)

## Data Model — Migration `0006_r3_profile_fields.sql` (additive only)

```sql
alter table leads add column if not exists weight_kg          numeric;
alter table leads add column if not exists sleep_bedtime      text;      -- "HH:MM"
alter table leads add column if not exists sleep_waketime     text;      -- "HH:MM"
alter table leads add column if not exists exercise_freq      text;      -- '0' | '1-2' | '3-4' | 'daily'
alter table leads add column if not exists pcos_status        text;      -- 'yes' | 'unsure' | 'no'
alter table leads add column if not exists behaviors          jsonb default '[]'::jsonb;  -- stage=male: ['smoke','alcohol','stress']
alter table leads add column if not exists partner_profile    jsonb default '{}'::jsonb;  -- R7: ข้อมูลฝ่ายชายเมื่อติ๊ก male_factor
alter table leads add column if not exists conception_method  text;      -- pregnant
alter table leads add column if not exists gestational_weeks  integer;   -- pregnant
alter table leads add column if not exists has_gdm            boolean default false; -- pregnant
```

**หมายเหตุ**
- `has_pcos` (boolean เดิม) **คงไว้** เพื่อ backward compat — เขียนค่าคู่กับ `pcos_status` (`has_pcos = (pcos_status === 'yes')`) ข้อมูลเก่าอ่านได้เหมือนเดิม
- `partner_profile` เก็บเป็น jsonb ก้อนเดียว (weight/height/sleep/exercise/behaviors) แทนการเพิ่ม 6 คอลัมน์ — ข้อมูลของคนละคนกับเจ้าของ record
- ไม่มีการ alter/drop คอลัมน์เดิม ตามกติกา additive-only ของโปรเจกต์

## Success Metrics

**Leading (วัดได้ใน 1–4 สัปดาห์)**
- % ผู้กรอกที่กรอกฟิลด์ใหม่ครบ (น้ำหนัก/ส่วนสูง/นอน/ออกกำลังกาย) — เป้า ≥ 80% *(ถ้าต่ำกว่านี้แปลว่าฟอร์มยาวเกินไป ต้องตัด)*
- % ที่กด "ทักแอดมิน" จากรายงานฉบับใหม่ เทียบกับโครงเดิม — เป้าไม่ต่ำกว่าเดิม *(ถ้าตกแปลว่าโครงใหม่ทำให้ CTA จมหาย)*
- อัตราเลิกกลางคัน (drop-off) รายขั้นตอน — โดยเฉพาะขั้นใหม่ R7 (ฟอร์มฝ่ายชาย) ที่เพิ่มความยาว flow

**Lagging (1–3 เดือน)**
- อัตราแอดมินต้อง "แก้คำแนะนำใหม่ทั้งหมด" ตอนคุยใน LINE — เป้า **ลดลงชัดเจน** (นี่คือ metric ที่ตรงกับ problem statement ที่สุด — ต้องให้ทีม LINE OA รายงานเอง ระบบไม่มีข้อมูลนี้)
- อัตราปิดการขายจาก ticket
