## 0. ภาพรวม
เฟส 1–2 สร้าง "ท่อรับ lead ใหม่" ได้แล้ว **เฟส 3 คือการเปลี่ยน LINE OA เดิมที่มีฐานลูกค้าอยู่แล้ว ให้กลายเป็น CRM (ระบบบริหารความสัมพันธ์ลูกค้า) ที่ใช้งานได้จริง**

### 📏 ขนาดฐานจริง: **150,000 คน** (ยืนยัน 2026-07-26)
ตัวเลขนี้**เปลี่ยนสมการทั้งหมด** และเป็นเหตุผลที่สเปกฉบับนี้แก้ไขครั้งที่ 2:
- ยิง broadcast ถึงทุกคน **1 ครั้ง = 150,000 ข้อความ** → ค่าใช้จ่ายระดับหลักหมื่นบาทต่อครั้ง (ดู §10)
- ฐานสะสมมานาน คนจำนวนมาก**ไม่ได้อยู่ในช่วงเตรียมท้องแล้ว** → ยิงเหมารวมคือจ่ายเงินเพื่อให้คนรำคาญ
- อัตราบล็อกแค่ 1% ของ 150,000 = **เสียผู้ติดตาม 1,500 คนถาวร** (LINE ไม่คืนให้)

> **หลักการใหม่ที่คุมทั้งเฟส 3:**
> ## 🚫 ไม่ยิงหาทุกคน — ใช้ช่องทางฟรีให้หมดก่อน แล้วค่อยจ่ายเงินเฉพาะกลุ่มเล็กที่คัดมาแล้ว
> ระบบจะ**บล็อกการยิงเกินเพดานด้วยโค้ด** ไม่ใช่แค่เขียนเป็นนโยบาย (ดู §4 F0 + §10)

### แก่นของปัญหา
> **เพื่อนใน LINE OA ทุกคนเป็นแค่รหัสนิรนาม (userId) จนกว่าเขาจะ "แตะ" เราหนึ่งครั้ง**
> เรามีฐาน 150,000 คน แต่ไม่รู้ว่าใครเป็นใคร อยู่ช่วงไหน เคยซื้ออะไร → คุยแบบเข้าใจไม่ได้ ยิงตรงกลุ่มไม่ได้

เฟส 3 แก้ 3 ชั้นตามลำดับ:
1. **รู้จักเขา (Identity)** — Epic D
2. **จำเขาได้ (Memory)** — Epic E
3. **คุยกับเขาให้ถูกคน ถูกเวลา (Reach)** — Epic F + G

### สิ่งที่ **ไม่ทำ** ในเฟส 3 (Non-goals — กัน scope creep)
- ❌ **ไม่สร้างหน้าจอแชทของเราเอง** — แอดมินยังใช้ LINE Official Account Manager / แอป LINE OA เหมือนเดิม (เขาคุ้นแล้ว และ LINE ทำได้ดีอยู่แล้ว) เราทำ "ชั้นสมอง" ไม่ใช่ "กล่องแชท"
- ❌ ไม่ทำระบบขาย/ตะกร้า/ชำระเงินในเฟสนี้
- ❌ ไม่ทำ AI ตอบแชทอัตโนมัติแทนคน (ผิดเส้นแดง compliance เรื่องคำแนะนำสุขภาพ)
- ❌ ไม่ดึงประวัติแชทเก่าย้อนหลัง (LINE ไม่มี API ให้ และเป็นข้อมูลอ่อนไหว)

## 1.5 บันไดการเข้าถึง (Reach Ladder) — หัวใจของสเปกฉบับแก้ไข
> ต้องไต่จากขั้นล่างขึ้นบน **ห้ามข้ามขั้น** · ขั้นบนปลดล็อกได้ก็ต่อเมื่อขั้นล่าง "ตันแล้ว" และพิสูจน์ด้วยตัวเลข

| ขั้น | ช่องทาง | เข้าถึงได้กี่คน | ต้นทุน | เพดานที่ระบบบังคับ |
|---|---|---|---|---|
| **0** | **Rich Menu** (เมนูล่าง) | **ทั้ง 150,000 คน** — ทุกคนที่เปิดห้องแชทเห็น | **฿0 ตลอดกาล** | ไม่มี ใช้ได้ไม่จำกัด |
| **0** | ข้อความต้อนรับ + ตอบอัตโนมัติตามคีย์เวิร์ด | ทุกคนที่ทักมา | **฿0** | ไม่มี |
| **0** | **LINE VOOM** | ผู้ติดตามที่ตาม VOOM | **฿0** | ไม่มี |
| **0** | นอก LINE: เว็บ · Facebook · IG · QR บนกล่องสินค้า · ใบเสร็จ | ไม่จำกัด | ฿0 (ต้นทุนสื่อเดิม) | ไม่มี |
| **1** | ทีมทัก 1:1 ในโหมดแชท | คนที่คุยค้าง | ฿0 | ตามกำลังคน |
| **2** | **ยิงเฉพาะกลุ่มที่คัดแล้ว** (narrowcast) | **หลักร้อย–ไม่เกิน 5,000** | เสียเงิน | 🔒 **ระบบบล็อกเกิน 5,000/แคมเปญ** |
| **3** | ยิงทุกคน (broadcast 150,000) | 150,000 | **หลักหมื่นบาท/ครั้ง** | 🚫 **ปิดตายในระบบ** — ปลดล็อกได้เฉพาะ admin + กรอกเหตุผล + ยืนยัน 2 ชั้น |

**ทำไมขั้น 0 ถึงพอ:** เมนูล่างอยู่ในห้องแชทของทั้ง 150,000 คนตลอดเวลา **โดยไม่เสียเงินสักบาท** ทุกคนที่เปิดแชทมาด้วยเหตุผลใดก็ตามจะเห็นปุ่ม "เช็คความพร้อมมีลูก ฟรี" → นี่คือ**เครื่องเก็บ lead ที่ทำงาน 24 ชั่วโมงโดยไม่มีต้นทุนต่อหน่วย** ต่างจาก broadcast ที่จ่ายทุกครั้งที่ส่ง

**ขั้น 2 ใช้เมื่อไหร่:** เมื่อมีเหตุผลเฉพาะเจาะจงและกลุ่มถูกคัดมาแล้วจริง ๆ เช่น
- "คนที่กรอกฟอร์มค้างไว้ 200 คน" · "คนที่เคยกดลิงก์แต่ยังไม่ได้แผน 800 คน" · "คนที่ครบ 90 วัน 340 คน"
- ❌ **ไม่ใช่** "ส่งโปรโมชันให้ทุกคน"

## 2. Epic D — Identity Resolution
**เป้าหมาย:** เปลี่ยนผู้ติดตามนิรนาม → ลูกค้าที่รู้จัก โดย**เริ่มจากช่องทางที่ไม่เสียค่าข้อความก่อน**

### User Stories
- ในฐานะลูกค้าเก่า ฉันกดเมนูล่างใน LINE แล้วได้แผนเฉพาะตัวเลย **โดยไม่ต้องพิมพ์รหัสอะไร**
- ในฐานะทีม ฉันอยากรู้ว่าจากฐาน N คน เรารู้จักจริงกี่คนแล้ว และเพิ่มขึ้นวันละเท่าไหร่
- ในฐานะลูกค้าที่เคยกรอกฟอร์มบนเว็บ ฉันอยากให้ระบบรู้ว่า "คนใน LINE" กับ "คนที่กรอกฟอร์ม" คือคนเดียวกัน

### D1 · LIFF Connect (P0) — เสาหลัก
- [ ] สร้าง LIFF app ผูกกับ LINE Login channel ของแบรนด์ → หน้า `/liff/connect`
- [ ] `liff.init()` → `liff.getIDToken()` → **ส่ง ID token ไปให้เซิร์ฟเวอร์ตรวจสอบกับ LINE (`/oauth2/v2.1/verify`)**
  - 🔒 **ห้ามเชื่อ `userId` ที่ส่งมาจากเบราว์เซอร์ตรง ๆ** (ปลอมได้) — ต้องยืนยันฝั่งเซิร์ฟเวอร์เสมอ ตามหลัก BFF ของโปรเจกต์
- [ ] เมื่อยืนยันแล้ว → upsert `line_profiles` + สร้าง/ผูก `customers` → เก็บ `source` ว่ามาจากช่องทางไหน (rich menu / broadcast / เว็บ)
- [ ] ถ้าคนนี้เคยกรอกฟอร์มมาก่อน (มี `lead`) → ผูกเข้าด้วยกันอัตโนมัติ แล้วพาไปที่รายงานเดิม ไม่ต้องกรอกซ้ำ
- [ ] ถ้ายังไม่เคย → พาเข้าแบบสอบถาม `/plan` โดย**ข้ามขั้นตอนถามช่องทางติดต่อ** (เรารู้ LINE เขาแล้ว) → ลดแรงเสียดทาน
- [ ] รองรับเปิดนอกแอป LINE ด้วย (fallback เป็นหน้าเว็บปกติ + ให้กรอกรหัสตั๋วแบบเดิม)

### D2 · Rich Menu 2 แบบ (P0) — ฟรี ได้ผลทุกวัน
- [ ] **เมนู A "ยังไม่รู้จัก"** (ค่าเริ่มต้นของทุกคน): ปุ่มเด่น **"เช็คความพร้อมมีลูก ฟรี"** → LIFF
- [ ] **เมนู B "รู้จักแล้ว"** (ผูกอัตโนมัติหลัง connect): "แผน 90 วันของฉัน" · "วันไข่ตกเดือนนี้" · "คุยกับทีมครูก้อย" · "สินค้าที่แนะนำสำหรับฉัน"
- [ ] สลับเมนูรายคนอัตโนมัติเมื่อผูกสำเร็จ / เมื่อ unfollow แล้ว follow ใหม่
- [ ] หน้าจัดการเมนูใน `/crm/settings/line` (อัปโหลดภาพ + ผูก/ถอด + ดูว่าใครใช้เมนูไหน)

### D3 · Webhook ขยาย (P0)
เพิ่มจากเฟส 2 (ซึ่งจับแค่ข้อความที่มีรหัส MJ-XXXXXX):
- [ ] `follow` → สร้าง `line_profiles` (สถานะ `active`) + บันทึก `interactions` + ส่งข้อความต้อนรับ (reply = ฟรี) + ผูกเมนู A
- [ ] `unfollow` → ตั้งสถานะ `blocked` + บันทึกเวลา → **ตัดออกจากทุก segment อัตโนมัติ** (กันยิงทิ้งเปล่า/เสียเงินฟรี)
- [ ] `message` (ทุกข้อความ ไม่ใช่แค่มีรหัส) → บันทึก `interactions` type=`inbound` + อัปเดต `last_active_at` (ไม่เก็บเนื้อความโดยค่าเริ่มต้น — ดู §9)
- [ ] `postback` → รองรับปุ่มใน Flex เช่น "หยุดรับข่าวสาร" / "ตอนนี้ฉันท้องแล้ว" / "ฉันยังพยายามอยู่"
- [ ] คงพฤติกรรมเดิมทั้งหมด (ตรวจ signature, ตอบ 200 เสมอ, จับรหัสตั๋ว)

### D4 · Backfill ฐานเดิม 150,000 คน (P0)
- [ ] งานหลังบ้าน (admin action + ทำงานเป็นก้อนในพื้นหลัง): ดึง `followers/ids` ทีละหน้า (1,000/หน้า ≈ **150 รอบ**) → สร้าง `line_profiles` สถานะ `anonymous`
- [ ] ⛔ **ห้ามดึงโปรไฟล์ทั้ง 150,000 คน** — จะเป็น 150,000 การเรียก API โดยไม่มีประโยชน์ตอบแทน
      → **ดึงโปรไฟล์เฉพาะตอนเขามีปฏิสัมพันธ์จริง** (ทัก / กดเมนู / เชื่อมต่อ) แบบ lazy
- [ ] ทำงานต่อจากจุดที่ค้างได้ (resume ด้วย cursor) ถ้าถูกขัดจังหวะ

## 3. Epic E — Customer 360
**เป้าหมาย:** แอดมินเปิดดูใครสักคนแล้ว **"เข้าใจเขาได้ใน 10 วินาที"** ก่อนพิมพ์ตอบใน LINE

### User Stories
- ในฐานะแอดมิน เมื่อมีคนทักเข้ามา ฉันอยากรู้ทันทีว่าเขาคือใคร อยู่ช่วงไหน เคยได้แผนอะไรไป เคยคุยอะไรค้างไว้
- ในฐานะหัวหน้าทีม ฉันอยากมอบหมายว่าใครดูแลลูกค้าคนไหน และเห็นว่าค้างตอบกี่ราย
- ในฐานะเจ้าของแบรนด์ ฉันอยากรู้ว่าฐานลูกค้าเรา "สุขภาพดี" แค่ไหน

### E1 · Customer 360 (P0)
หน้า `/crm/c/[id]` — 4 บล็อกในหน้าเดียว:
1. **หัวการ์ด:** ชื่อเล่น + ชื่อ LINE + รูป + ช่วงชีวิต + อายุ + คะแนนความพร้อมล่าสุด + แท็กทั้งหมด + สถานะ (ใหม่/กำลังคุย/ปิด) + ผู้รับผิดชอบ
2. **ไทม์ไลน์:** ทุกเหตุการณ์เรียงเวลา — กรอกฟอร์ม · ใช้เครื่องมือไหน · เปิดรายงานกี่ครั้ง · ทักเข้ามา · เราส่งอะไรไป · กดลิงก์อะไร · ซื้ออะไร
3. **โน้ตทีม:** บันทึกภายใน (ใครเขียน เมื่อไหร่) — **ไม่แสดงให้ลูกค้าเห็น**
4. **แผงลงมือ:** ปุ่ม "เปิดแชทคนนี้ใน LINE" · เพิ่ม/ลบแท็กมือ · เปลี่ยนสถานะ · มอบหมายคน · ส่งรายงานซ้ำ · **ดาวน์โหลด/ลบข้อมูลตามคำขอเจ้าของข้อมูล (PDPA)**

### E2 · รายชื่อลูกค้า (P0)
- [ ] ยกระดับ `/leads` เดิม → `/crm/customers` (คง `/leads` เป็น redirect เพื่อไม่ทำลิงก์เก่าพัง)
- [ ] เพิ่มตัวกรอง: สถานะการรู้จัก (นิรนาม/รู้จัก/บล็อก) · แท็ก · ผู้รับผิดชอบ · ใช้งานล่าสุด · เคยซื้อ/ไม่เคย
- [ ] เลือกหลายรายการ → เพิ่มแท็ก / มอบหมาย / **สร้าง segment จากผลค้นหานี้** (สะพานไปยัง Epic F)

### E3 · แดชบอร์ดสุขภาพฐาน (P0)
หน้า `/crm` — ตัวเลขที่เจ้าของแบรนด์ควรเห็นทุกเช้า:
- ผู้ติดตามทั้งหมด · **รู้จักแล้วกี่คน (%)** · เพิ่มใหม่ / บล็อก (7 & 30 วัน) · **โควตาข้อความเดือนนี้ใช้ไปเท่าไหร่**
- กราฟ "อัตราการรู้จัก" รายสัปดาห์ (ตัวชี้วัดหลักของเฟส 3)
- สัดส่วนช่วงชีวิตของฐานที่รู้จัก (เตรียมท้อง / มีบุตรยาก / ท้องแล้ว / ให้นม / ชาย)
- ⚠️ กล่องเตือน: "มี X คนค้างตอบเกิน 24 ชม."

**Definition of Done (Epic E):** แอดมินเปิดหน้าลูกค้าหนึ่งคน เห็นครบทุกอย่างที่ต้องใช้ตอบแชท โดยไม่ต้องเปิดหน้าอื่น

## 4. Epic F — Segment → Audience → Campaign
**เป้าหมาย:** ยิง 800 คนที่ใช่ ดีกว่ายิง 150,000 คนมั่ว — และ **รู้ต้นทุนก่อนกดส่งเสมอ**

### F0 · เพดานที่บังคับด้วยโค้ด (P0) — **ข้อกำหนดใหม่จากขนาดฐาน 150,000**
- [ ] **เพดานผู้รับต่อแคมเปญ = 5,000 คน** (ตั้งค่าได้) → เกินกว่านี้ **ปุ่มส่งถูกปิด** ไม่ใช่แค่ขึ้นคำเตือน
- [ ] ปลดเพดานได้เฉพาะ: role `admin` **+** กรอกเหตุผลเป็นข้อความ **+** ยืนยันซ้ำโดยพิมพ์จำนวนผู้รับเอง **+** บันทึกลง `staff_audit` ว่าใครปลดและเพราะอะไร
- [ ] **เพดานงบรายเดือน** (บาท) ตั้งได้ → ระบบรวมต้นทุนของทุกแคมเปญในเดือนนั้น เกิน 80% เตือน **เกิน 100% ปิดปุ่มส่งทั้งระบบ**
- [ ] 🚦 **ด่านช่องทางฟรี:** ก่อนสร้างแคมเปญที่เสียเงิน ระบบแสดง "ช่องทางฟรีที่ยังไม่ได้ใช้" (เมนูล่างล่าสุดอัปเดตเมื่อไหร่ · มีคีย์เวิร์ดตอบอัตโนมัติกี่คำ · โพสต์ VOOM ล่าสุดเมื่อไหร่) — **ต้องกดรับทราบก่อนไปต่อ**

### F1 · ตัวสร้างกลุ่ม (P0)
- [ ] เงื่อนไขแบบต่อกันได้ (AND/OR): ช่วงชีวิต · แท็ก · ช่วงอายุ · PCOS · แผน ART · คะแนนความพร้อม · ใช้งานล่าสุด · เคยเปิดรายงานไหม · เคยซื้อไหม · **ยินยอมรับข่าวสารไหม (บังคับ)**
- [ ] แสดง **จำนวนคนที่เข้าเงื่อนไขแบบสด** ขณะปรับเงื่อนไข
- [ ] บันทึกเป็น segment ตั้งชื่อได้ · เลือกได้ว่าเป็นแบบ **สด (dynamic)** หรือ **แช่แข็ง ณ เวลานั้น (snapshot)**
- [ ] 🔒 **ตัดออกอัตโนมัติเสมอ:** คนที่บล็อก · คนที่ไม่ยินยอมรับข่าวสาร · คนที่ชนเพดานความถี่ · คนที่ไม่มี `line_user_id`

### F2 · ส่งกลุ่มเข้า LINE เป็น Audience (P0)
- [ ] ปุ่ม "ส่งเข้า LINE" → สร้าง Audience → เก็บ `audience_group_id` + สถานะ (`IN_PROGRESS` / `READY` / `FAILED`)
- [ ] ทยอยส่งเป็นก้อนตามลิมิตของ LINE + ลองใหม่เมื่อพลาด
- [ ] เมื่อ `READY` → ใช้ได้ทั้งใน**ระบบเรา** (narrowcast) และใน **OA Manager** (ทีมเลือกกลุ่มนี้ตอนทำ broadcast เองได้)
- [ ] ซิงก์ซ้ำได้เมื่อสมาชิกกลุ่มเปลี่ยน (สร้าง audience ใหม่ + เลิกใช้ตัวเก่า)

### F3 · ตัวเขียนแคมเปญ 3 ขั้น (P0)
1. **เลือกกลุ่ม** → เห็นจำนวนคนจริงหลังหักคนที่ถูกตัดออก + **ประมาณการต้นทุน**
2. **เขียนข้อความ** → ข้อความ / Flex การ์ด / รูป · แทรกชื่อเล่นได้ · **ตัวอย่างแสดงเป็นหน้าจอ LINE จริง** · ✅ ตัวตรวจ compliance อัตโนมัติ (คำต้องห้าม: "รักษา", "หายขาด", "การันตี", "ท้องแน่นอน") · **บังคับมีปุ่มหยุดรับข่าวสาร**
3. **ตรวจ & ส่ง** → สรุปทั้งหมด + ต้นทุน + **ส่งทดสอบหาตัวเองก่อนเสมอ** + ตั้งเวลา/แบ่งระลอกได้ → ต้องมีสิทธิ์ `send_campaign` จึงกดได้
   - [ ] **เครื่องจำลองต้นทุน:** เลื่อนจำนวนผู้รับแล้วเห็นราคาเปลี่ยนทันที + เทียบข้าง ๆ ว่า "ถ้าใช้เมนูล่าง/VOOM แทน = ฿0"
   - [ ] แสดง **"ต้นทุนต่อคนที่คาดว่าจะเชื่อมต่อ"** จากอัตราแปลงของแคมเปญก่อนหน้า — ตัวเลขนี้คือสิ่งที่ใช้ตัดสินใจจริง ไม่ใช่ยอดรวม

### F4 · ผลลัพธ์ (P0)
- [ ] ต่อคนต่อแคมเปญ: ส่งสำเร็จ · เห็น · กดลิงก์ · **บล็อกหลังได้รับ**
- [ ] ผูกกลับเข้าไทม์ไลน์ของลูกค้าแต่ละคน
- [ ] เทียบ 2 ข้อความ (A/B) แบบง่าย: แบ่งกลุ่มครึ่ง-ครึ่ง (P1)

**Definition of Done (Epic F):** สร้างกลุ่ม → เห็นจำนวน+ต้นทุน → ส่งทดสอบ → ส่งจริงเป็นระลอก → เห็นผลรายคน และเห็นในไทม์ไลน์

## 5. Epic G — Lifecycle Automation
**เป้าหมาย:** ส่งของที่มีประโยชน์ "ถูกเวลา" โดยไม่ใช้แรงคน — และ**ไม่รบกวน**

### G1 · เครื่องยนต์ (P1)
- [ ] นิยาม journey แบบ: **ทริกเกอร์ → เงื่อนไข → รอ → ส่ง → เงื่อนไขหยุด**
- [ ] ทำงานด้วยงานตามเวลา (cron) รายชั่วโมง · idempotent (ส่งซ้ำไม่ได้)
- [ ] **เงื่อนไขหยุดสากล:** ถ้าเขาทักเข้ามาเอง = หยุด journey ทันที (มนุษย์เข้าคุยแล้ว อย่าให้บอทแทรก)

### G2 · Journey ชุดแรก (P1)
| ชื่อ | ทริกเกอร์ | ส่งอะไร | ทำไม |
|---|---|---|---|
| ยังไม่เปิดรายงาน | กรอกครบแล้ว 48 ชม. แต่ยังไม่เปิด | เตือน 1 ครั้ง + ลิงก์ | รายงานคือคุณค่าหลัก อย่าให้ตกหล่น |
| ครบ 30 / 60 / 90 วัน | ผูก LINE + มีแผน 90 วัน | "เช็คอินแผนของคุณ" + ปรับแผน | ทำให้แผนมีชีวิต ไม่ใช่ไฟล์ตาย |
| หน้าต่างไข่ตก | มีข้อมูลรอบเดือน + **ขอรับเตือน** | เตือนล่วงหน้า 2 วัน | มีประโยชน์จริง ทำให้เขารอข้อความเรา |
| เงียบไป 60 วัน | ไม่มีกิจกรรมเลย | ถามไถ่ 1 ครั้ง + ปุ่ม "หยุดรับข่าวสาร" | ปลุกก่อนหาย ไม่ตื๊อ |
| ชวนคู่ | ผู้หญิงที่ยังไม่มีข้อมูลฝ่ายชาย | การ์ดส่งต่อให้สามี | ปัจจัยฝ่ายชาย ~40% (อ้าง PRD-PHASE2) |

- [ ] ⚠️ **ข้อห้ามเชิงจริยธรรม:** ห้ามส่งอัตโนมัติเกี่ยวกับผลตั้งครรภ์/แท้ง/รอบเดือนที่ตีความว่า "ล้มเหลว" · ห้ามใช้ความกลัวเป็นแรงจูงใจ · ทุก journey ต้องผ่าน red-team (lucifer) ก่อนเปิดใช้
- [ ] คนที่กด "ตอนนี้ฉันท้องแล้ว" → **ย้ายออกจาก journey เตรียมท้องทั้งหมดทันที**

## 9. NFR
### ความปลอดภัย
- 🔒 **ยืนยัน LIFF ID token ฝั่งเซิร์ฟเวอร์เสมอ** — ห้ามเชื่อ userId จากเบราว์เซอร์
- 🔒 LINE access token / channel secret อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น (ไม่มี `NEXT_PUBLIC_`)
- 🔒 ตรวจ `x-line-signature` ทุก webhook (มีแล้ว) · ตอบ 200 เสมอ
- 🔒 ทุกการกระทำที่มีผลภายนอก (ส่งแคมเปญ / ดึงฐาน / ลบข้อมูล) บันทึก `staff_audit` ว่าใครทำ
- 🔒 จำกัดอัตราเรียก API ของเราเอง เพื่อไม่ให้โดน LINE จำกัด

### PDPA — เส้นแดง
- **แยกความยินยอม 3 ประเภท** (`consents.kind`): ข้อมูลสุขภาพ (ม.26 · ต้องชัดแจ้ง) / การตลาด / การรับข้อความ LINE
- ผู้ติดตามเดิม **ยินยอมแค่รับข่าวสารจาก OA** → **ห้ามผูกข้อมูลสุขภาพกับเขาจนกว่าจะกดยินยอมเอง**
- ทุกข้อความการตลาด **ต้องมีทางถอน** (ปุ่ม postback "หยุดรับข่าวสาร") → บันทึกทันที + ตัดออกทุก segment
- **ไม่เก็บเนื้อความแชทโดยค่าเริ่มต้น** — เก็บแค่ "มีข้อความเข้ามาเมื่อไหร่" (เก็บเนื้อความต้องเป็นการตั้งค่าที่เจ้าของแบรนด์เปิดเอง + แจ้งในนโยบาย)
- **นโยบายเก็บข้อมูล:** ไม่มีกิจกรรม 24 เดือน → ทำให้ไม่ระบุตัวตน (anonymize) โดยอัตโนมัติ
- รองรับคำขอเจ้าของข้อมูล (ขอดู / ขอแก้ / ขอลบ) จากหน้า Customer 360
- อัปเดต `/privacy` ให้ครอบคลุมการใช้ข้อมูลเพื่อ CRM + การส่งข้อความการตลาด ✍️ **ต้องให้เจ้าของแบรนด์ตรวจ**

### ประสิทธิภาพ
- LIFF connect → เห็นผลภายใน **2 วินาที** (คนอยู่บนมือถือ 4G)
- Customer 360 โหลด < 1.5 วินาที (ไทม์ไลน์แบ่งหน้า 50 รายการ)
- Backfill / campaign เป็นงานพื้นหลังทั้งหมด — ไม่บล็อกหน้าจอ

## 10. ต้นทุน
> **หลักการ:** ทุก push/broadcast = เงินจริง ต่อคน ต่อข้อความ · reply = ฟรี → **ออกแบบให้ "เขาทักมา" มากกว่า "เรายิงไป"**

### ทำไมต้องเข้มขนาดนี้ — คณิตศาสตร์ของฐาน 150,000 คน
> ⚠️ **ราคาต่อข้อความในตารางนี้เป็นตัวเลขสมมติเพื่อแสดงลำดับความใหญ่เท่านั้น ไม่ใช่ราคาจริงของ OA ครูก้อย** — ต้องกรอกราคาจริงจากแพ็กเกจของแบรนด์ในหน้าตั้งค่า แล้วระบบคำนวณให้เอง

| ยิงกี่คน | ที่ ฿0.02/ข้อความ | ที่ ฿0.05/ข้อความ | ที่ ฿0.10/ข้อความ |
|---|---|---|---|
| **150,000 (ทุกคน)** | ฿3,000 | ฿7,500 | **฿15,000 ต่อการยิง 1 ครั้ง** |
| 20,000 | ฿400 | ฿1,000 | ฿2,000 |
| **5,000 (เพดานที่ระบบบังคับ)** | ฿100 | ฿250 | ฿500 |
| **1,500 (ทดสอบวัดราคาต่อหัว)** | ฿30 | ฿75 | ฿150 |

**ต้นทุนแฝงที่แพงกว่าค่าข้อความมาก:** ถ้ายิง 150,000 คนแล้วมีคนบล็อกแค่ 1% = **เสียผู้ติดตาม 1,500 คนถาวร** LINE ไม่คืนให้ และการหาผู้ติดตามใหม่แพงกว่าค่าข้อความหลายเท่า
> **นี่คือเหตุผลที่แท้จริงของการห้ามยิงเหมารวม — ไม่ใช่แค่ประหยัดเงิน แต่คือการไม่เผาสินทรัพย์ที่แบรนด์สะสมมาหลายปี**

### Guardrail ที่ต้องเขียนลงโค้ด (ไม่ใช่แค่นโยบาย)
1. 🔒 **เพดานผู้รับต่อแคมเปญ 5,000 คน** — เกินแล้ว **ปุ่มส่งถูกปิด** ปลดได้เฉพาะ admin + กรอกเหตุผล + ยืนยันซ้ำ (ดู §4 F0)
2. 🔒 **เพดานงบรายเดือนเป็นบาท** — เกิน 80% เตือน · **เกิน 100% ปิดปุ่มส่งทั้งระบบ**
3. **เพดานความถี่รายคน:** ข้อความการตลาดไม่เกิน **4 ครั้ง/เดือน** เว้นห่าง ≥ **48 ชม.** — คนที่ชนเพดานถูกตัดออกจาก segment อัตโนมัติ (พร้อมเหตุผล `skip_reason`)
4. **ด่านช่องทางฟรี:** ต้องกดรับทราบรายการช่องทางฟรีที่ยังไม่ได้ใช้ ก่อนสร้างแคมเปญที่เสียเงิน
5. **ส่งเป็นระลอกบังคับ:** เกิน 1,000 คน ต้องแบ่งอย่างน้อย 3 ระลอก เว้นระยะ ≥ 6 ชม.
6. **เบรกอัตโนมัติ:** อัตราบล็อกของระลอกใดเกิน **1.5%** → **หยุดระลอกที่เหลือทันที** + แจ้งแอดมิน
   *(ค่าเริ่มต้นที่เราตั้งเอง ⚠️ ไม่ใช่ค่ามาตรฐานอุตสาหกรรมที่อ้างอิงได้ — ควรปรับหลังเห็นข้อมูลจริงจากการทดสอบครั้งแรก)*
7. **ส่งทดสอบก่อนเสมอ** — กดส่งจริงไม่ได้ถ้ายังไม่เคยส่งทดสอบ
8. **แสดงต้นทุนรวม + "ต้นทุนต่อคนที่คาดว่าจะเชื่อมต่อ" ก่อนกดเสมอ** พร้อมเทียบข้าง ๆ กับทางเลือกฟรี (เมนูล่าง / VOOM)

## 11. KPI
| ตัวชี้วัด | นิยาม | เป้าเริ่มต้น |
|---|---|---|

| **สัดส่วนการเชื่อมต่อที่ไม่เสียเงิน (ตัวคุมวินัย)** | ผูกผ่านเมนูล่าง/ตอบอัตโนมัติ/VOOM/นอก LINE | **≥ 90%** ของการผูกทั้งหมด |

| **ต้นทุนต่อคนที่รู้จัก 1 คน** | ค่าข้อความ ÷ คนที่เชื่อมต่อใหม่จากช่องทางเสียเงิน | ตัวเลขที่ใช้ตัดสินใจว่าจะจ่ายต่อไหม — ถ้าแพงกว่าค่าโฆษณา **ให้หยุด** |
| อัตราการกรอกจนจบ | คนที่เข้า LIFF แล้วได้รายงาน | ≥ 55% |
| **อัตราบล็อกจากแคมเปญ** | บล็อกภายใน 24 ชม.หลังได้รับ | **< 1%** (เกิน 1.5% = เบรกอัตโนมัติ) |
| อัตราตอบกลับของทีม | ตอบภายใน 24 ชม. | ≥ 90% |

> ⚠️ **เป้า 5% (7,500 คน) เป็นสมมติฐานของเรา ไม่ใช่ตัวเลขที่มีข้อมูลรองรับ** — ขึ้นกับว่าเดือนหนึ่งมีคนเปิดห้องแชท OA กี่ % ซึ่งเรายังไม่รู้ **ให้วัดจริงในสัปดาห์แรกหลังเปลี่ยนเมนูล่าง แล้วปรับเป้า** อย่ายึดตัวเลขนี้เป็นคำมั่น
