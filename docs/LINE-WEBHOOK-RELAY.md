# อยู่ร่วมกับบอทเช็คสลิป Thunder บน LINE OA เดียวกัน

> อัปเดต 12 ส.ค. 2569 · โค้ด: [`lib/line-relay.ts`](../lib/line-relay.ts) · [`app/api/line/webhook/route.ts`](../app/api/line/webhook/route.ts) · เทสต์: [`lib/line-relay.test.ts`](../lib/line-relay.test.ts)

## ปัญหา

LINE OA ตั้ง **Webhook URL ได้ช่องเดียวเท่านั้น** — OA ของ Baby & Mom มีบอทเช็คสลิปของ Thunder (`line.thunder.in.th`) จองช่องนั้นอยู่ก่อนแล้ว webhook ของ Mommunjai จึงไม่เคยถูกเรียกเลย

**ทางที่ตัดทิ้งไปแล้ว:** ให้ Thunder ส่งต่อ webhook มาให้เรา — ต้นตรวจ API doc ของ Thunder แล้ว (12 ส.ค. 2569) **ไม่มีฟีเจอร์นี้** (`document.thunder.in.th` เป็น API ตรวจสลิปธนาคาร ไม่เกี่ยวกับ LINE webhook เลย)

## วิธีที่ใช้ — เราเป็นตัวรับ แล้วส่งต่อให้ Thunder

```
LINE Platform
     │  (ตั้ง Webhook URL ชี้มาที่นี่)
     ▼
/api/line/webhook  ── ส่งต่อ body ดิบ + ลายเซ็นเดิม ──▶  line.thunder.in.th (บอทเช็คสลิป)
     │
     └─ ตอบเฉพาะ "แผนของฉัน" กับ "MJ-XXXXXX" · นอกนั้นเงียบสนิท
```

## 🔴 3 กฎที่ผิดแล้วระบบเก็บเงินของลูกค้าพัง

### 1. body ต้องตรงต้นฉบับทุกไบต์
ลายเซ็น LINE คำนวณจาก body ดิบ ขยับแม้แต่ช่องว่างเดียว Thunder จะตีตกทุก event
→ โค้ดส่ง `raw` จาก `await req.text()` ตรง ๆ **ห้าม `JSON.parse` แล้ว `stringify` ใหม่**
→ มีเทสต์คุมไว้: *"ส่ง body ตรงทุกไบต์ + header x-line-signature เดิม"*

### 2. `replyToken` ใช้ได้ครั้งเดียว
ถ้าเราตอบข้อความที่ไม่ใช่ของเรา Thunder จะตอบไม่ได้ → **คนโอนเงินจะได้ข้อความ "พิมพ์รหัส MJ-XXXXXX" แทนผลตรวจสลิป**
→ พอ `LINE_RELAY_WEBHOOK_URL` ถูกตั้ง เราจะ**เงียบ**กับทุกข้อความที่ไม่ใช่ `"แผนของฉัน"` หรือ `MJ-XXXXXX`
→ มีเทสต์คุมไว้: *"โหมด relay: ข้อความทั่วไปต้องเงียบสนิท แต่ยังส่งต่อครบ"*

### 3. Thunder ต้องได้ของเสมอ ถึงงานเราจะพัง
- เริ่มส่งต่อ**ก่อน**ทำงานอะไรของเรา แล้ว `await` ตอนท้ายก่อน `return`
  (Vercel ตัดฟังก์ชันทิ้งทันทีที่ return — ยิงแบบ fire-and-forget แล้วไม่รอ event จะหายเป็นช่วง ๆ แบบหาสาเหตุยากมาก)
- `relayToPartner()` **ไม่โยน exception ออกมาเลย** คืน result object แทน
- **fail-open:** ถ้า `LINE_CHANNEL_SECRET` ของเราหาย/ตั้งผิด → ยังส่งต่อ ให้ Thunder ตรวจลายเซ็นเอง (config พังฝั่งเรา ต้องไม่ทำบอทลูกค้าตาย)
- **fail-closed:** ถ้าตรวจได้แล้วไม่ผ่าน = ของปลอม → ไม่ส่งต่อ (ไม่เป็นทางผ่านให้คนยิงขยะใส่ Thunder)
- timeout 5 วินาที · ปลายทาง 5xx retry อีก 1 ครั้ง · 4xx ไม่ retry (ยิงซ้ำก็ได้ผลเดิม)

## ตั้งค่า

### 1) Vercel → Environment Variables

| ตัวแปร | ค่า | หมายเหตุ |
|---|---|---|
| `LINE_RELAY_WEBHOOK_URL` | `https://line.thunder.in.th/api/v1/webhook/350dfadf-facc-4571-88ea-468939da3b80` | **ไม่ตั้ง = โหมดเดิม** (เราเป็นบอทตัวเดียว ตอบทุกข้อความ) |
| `LINE_BOT_ENABLED` | `1` | kill switch (ดูข้างล่าง) |

### 2) LINE Developers Console → Messaging API

เปลี่ยน **Webhook URL** จากของ Thunder เป็น `https://<โดเมนของเรา>/api/line/webhook` แล้วกด **Verify**

> ⚠️ ขั้นตอนนี้ **ต้องได้สิทธิ์จากเจ้าของ LINE OA** และเป็นจุดที่ระบบสลิปจะสะดุดถ้าทำผิด
> ควรทำนอกเวลาขายของ และเตรียม URL เดิมไว้ paste กลับทันทีถ้ามีปัญหา

### 3) ทดสอบทันทีหลังเปลี่ยน (ห้ามข้าม)

1. ส่งข้อความอะไรก็ได้ที่ไม่ใช่ของเรา → **บอทสลิปต้องตอบเหมือนเดิม** และของเราต้องเงียบ
2. ส่งสลิปจริง 1 ใบ → ต้องได้ผลตรวจสลิปตามปกติ
3. พิมพ์ `แผนของฉัน` → ต้องได้การ์ดของเรา
4. พิมพ์รหัส `MJ-XXXXXX` → ต้องได้แผนเฉพาะบุคคล

## 🔴 KILL SWITCH — เมื่อบอทเราไปกวนบอทสลิป

**อาการที่ต้องกดทันที:** ลูกค้าส่งสลิปแล้วได้ข้อความของ Mommunjai ตอบกลับแทนผลตรวจสลิป

**วิธีกด:**
1. Vercel → Project → Settings → Environment Variables → ตั้ง `LINE_BOT_ENABLED = 0`
2. Deployments → กด **Redeploy** (~1 นาที)

**ผลลัพธ์:** งานฝั่ง Mommunjai หยุดทั้งหมด (ไม่ตอบอะไรเลย แม้แต่ `"แผนของฉัน"`) แต่**การส่งต่อไป Thunder ยังทำงานปกติ 100%** → ระบบเก็บเงินของลูกค้ากลับมาทันทีโดยไม่ต้องแตะ LINE Console

ค่าที่นับว่า "ปิด": `0` `false` `off` `no` (ไม่สนตัวพิมพ์เล็กใหญ่/ช่องว่าง) · ไม่ตั้งค่า = เปิด

> **ข้อจำกัดที่ต้องรู้:** env var ของ Vercel ไม่ได้อ่านสด ต้อง Redeploy ถึงมีผล
> ถ้าวันหนึ่งต้องการปิดได้ทันทีจริง ๆ ต้องย้าย flag ไปเก็บใน Supabase (แลกกับ query เพิ่มทุก event) — ยังไม่ทำในรอบนี้

**ทางถอยขั้นสุดท้าย** (ถ้า Vercel เข้าไม่ได้ / เราล่มทั้งระบบ): กลับไปตั้ง Webhook URL ใน LINE Developers เป็นของ Thunder ตามเดิม — บอทสลิปกลับมาทันที เสียแค่ฟีเจอร์ของเรา
